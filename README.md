# 拾光校园 · 校园失物招领

> 软件工程结对作业（第二次）· 代码实现
> 学号：102401208 · 102401133

一个校园失物招领的移动端 Web 应用，实现 **「发布信息 → 浏览/搜索 → 查看详情 → 联系发布者 → 更新状态」** 这条完整主流程。

---

## 一、使用说明

### 1. 运行（不需要安装任何东西）

下载本仓库全部文件后，**用谷歌浏览器（Chrome）打开根目录下的 `index.html`** 即可，无需 Node.js、无需起本地服务器、无需构建。

```
双击 index.html   ←  或者：右键 → 打开方式 → Google Chrome
```

> **注意**：本项目刻意做成了**零依赖的纯静态站点**，因此不能用 ES module、不能 `fetch` 读本地 JSON。
> 如果你习惯用 VS Code 的 Live Server 打开，也能正常运行，但不是必需的。
>
> 如果双击后没有用 Chrome 打开（比如被其他浏览器或看图软件抢占了 `.html` 关联），
> 请右键 → 打开方式 → Google Chrome，或把文件拖进已打开的 Chrome 窗口。

### 2. 跑单元测试（可选）

只有这一步需要 Node.js（v18 以上即可）：

```bash
npm install    # 只装一个 mocha，首次需要联网
npm test
```

预期输出：

```
  100 passing (60ms)
```

### 3. 建议的体验路径

1. 打开 `index.html`，看到首页「最新发布」
2. 点底部中间的 **「＋」** → 选择「发布寻物」或「发布招领」
3. 填写表单 → 点「确认发布」→ 看到「发布成功」页
4. 回到首页，刚发布的信息出现在「最新发布」**最顶部**
5. 刷新页面，信息仍在（存在浏览器 localStorage 里）
6. 进入「我的」→ 对本人发布的信息点「标记为已找到 / 已归还」
7. 在「我的」页**点任意一条记录**（整行都能点）→ 打开这条信息的详情页
8. 点记录右边的 **「⋯」→ 编辑** → 改完点「保存修改」→ 回到「我的」并提示「修改已保存」
9. 回到「我的」→ 点顶部的统计格（**全部发布 / 进行中 / 已完成**）→ 下面的记录只留这一种状态，
   三个数字本身不变（它们是筛选项，不是筛选结果）
10. 进「广场」→ 点右上角的 **「最新 ▾」** → 切成「最早发布在前」，列表倒过来（最早的在最上面）
11. 同一个下拉里选 **「近 7 天 / 近 30 天 / 近半年 / 近一年」** → 条数依次是 5 / 6 / 7 / 8，最后「全部时间」才凑齐 9 条

> 应用的「当前用户」固定为 **小白同学（计算机学院 2023级）**，用于演示「只有发布者本人能标记状态完成」这条规则。
> 想恢复初始数据：在「我的」页面点「恢复示例数据」，或在浏览器控制台执行 `LF.store.reset()`。

**为什么所有 HTML 都放在根目录？**
数据里存的图片路径形如 `assets/items/item-01.svg`。如果把页面放进子目录（如 `detail/index.html`），
从该页解析这个相对路径会变成 `detail/assets/...` 而 404。全部平铺在根目录可以让每条相对路径从任何页面都解析正确。

## 四、两个关键设计决定

### 1. 状态只有两个逻辑值

需求文档与设计稿里先后出现过 `寻找中 / 待认领 / 找到 / 已找回 / 寻找失主中 / 焦急寻找中 / 已完成`
七八种叫法。代码里统一收敛为 `state: 'open' | 'done'` 两个值，页面上显示的文案由 `LF.statusText()` 派生：

| | `open` | `done` |
| --- | --- | --- |
| 寻物 `lost` | 焦急寻找中（橙） | 已找到 |
| 招领 `found` | 寻找失主中（绿） | 已归还 |

好处是状态流转只有一条规则可判断，不需要为每种叫法各写一个分支。

### 2. 逻辑与界面分离，同一份代码既跑页面又跑测试

`js/core.js` 用 UMD 包裹：

```js
(function (root, factory) {
  if (typeof module === 'object' && module.exports) module.exports = factory();  // Node / Mocha
  else root.LF = factory();                                                      // 浏览器
})(typeof self !== 'undefined' ? self : this, function () { /* ... */ return LF; });
```

因此 `npm test` 测的是**页面上正在跑的那一份代码**，不存在「测试通过但页面走的是另一套逻辑」的情况。
`file://` 下 Chrome 会按 CORS 拦截 ES module，所以全站只用传统 `<script src>`，这也是选 UMD 而非 ESM 的原因。

## 五、已知限制

- 数据存在浏览器 **localStorage** 里，因此**换一个浏览器打开就是一份全新的数据**，且不同浏览器之间不互通。
  这是纯静态站点在没有后端时的必然结果，不影响功能演示。
- 「当前用户」是写死的演示身份，没有登录注册流程（作业未要求）。
- 隐私浏览模式或禁用了 localStorage 时，会自动降级为**内存存储**：功能全部可用，但关掉页面数据就没了。
